BrightpanAccounts payable

How a supplier document becomes accounts-payable data

Brightpan Kitchen Supply (fictional). Every document is read, checked and filed, or stopped for a person with the reason.

Intake

Email

Supplier sends a PDF, scan or photo to the AP address. n8n picks it up within a minute.

Gmail + n8n

Upload

Drag files into the AP web app.

Next.js + shadcn/ui
API and queue

Extraction API

Stores the file and answers at once (202 + id). Token-protected.

Python + FastAPI

Job queue

Documents wait in Postgres; two workers claim them, each read exactly once.

Postgres (Supabase)
Worker

Read, check, route

  1. Read PDF text layer, or page images for scans and photos
  2. Extract Claude, strict schema, confidence per field
  3. Validate required fields, dates, currency, lines = subtotal, subtotal − discount + tax + shipping = printed total (±$0.02)
  4. Duplicate check same vendor + invoice number
  5. Route any flag or low confidence goes to review
Claude + Pydantic
Outputs

AP register

Clean documents become a row in the Google Sheet. Approved review items too.

n8n + Google Sheets

Review queue

Wrong totals, duplicates, unreadable fields wait for a person, with the reason.

Web app + Slack

Never invents, never corrects

The printed total is kept and flagged when it is wrong. No due date is made up; a Canadian bill stays in CAD.

Keeps going when things fail

Rate limits and outages are retried, missed register rows and Slack alerts are resent, health checks show what is down.

Measured, not estimated

20-document test set: 200/200 fields, 79/80 line items, 2/2 planted errors caught, $0.025 per document.
